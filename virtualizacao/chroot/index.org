#+Title: chroot


* O que é um ambiente chroot (Resumo from perplexity)
O chroot é utilizado para:
  + isolar processos
  + realizar testes controlados
  + recuperar sistemas após falhas
  + aumentar a segurança do sistema.​

Quando você executa o comando chroot apontando para um diretório, todos os caminhos absolutos daqueles processos passam a ser relativos ao novo diretório raiz escolhido.

Exemplos de uso: recuperar bootloader, resetar senhas, testar softwares sem afetar o restante do sistema.​

Como funciona a configuração de um ambiente chroot
Primeiramente, cria-se uma estrutura de diretórios que servirá como novo root (geralmente copiando binários essenciais e suas bibliotecas dependentes para lá).​

Utiliza-se o comando chroot /caminho/para/novo/root comando para acessar essa "jaula".​

É comum copiar os seguintes diretórios para dentro do ambiente chroot: /bin, /lib, /lib64, /usr e /etc, garantindo a funcionalidade de comandos básicos.​

Para ambientes mais avançados, pode-se montar arquivos especiais como
/proc e /dev dentro do chroot.​

*** Instalando ferramenta mock: sudo dnf install mock
O mock cria um chroot limpo (ou container) no qual ele instala todas as dependências necessárias para compilar um pacote RPM a partir de seu arquivo .src.rpm ou especificação (.spec).
Assim, a compilação ocorre em um ambiente controlado, sem interferir
no seu sistema principal.

**** Ele é usado principalmente por:

Empacotadores (maintainers) do Fedora, EPEL e outras distros RPM.

Desenvolvedores que precisam gerar pacotes RPM consistentes e reproduzíveis.

Sistemas de CI/CD que automatizam a construção de pacotes.

**** Benefícios do uso

🔒 Isolamento — o build não polui o sistema.

🧹 Ambiente limpo — garante que o pacote declare todas as dependências necessárias.

♻️ Reprodutibilidade — builds idênticos em diferentes máquinas.

⚙️ Multi-distribuição — pode compilar para várias versões do Fedora/RHEL sem precisar mudar de sistema.

**** Exemplo prático

Suponha que você tenha um arquivo hello.spec.
Você pode criar o pacote assim:

mock -r fedora-40-x86_64 --buildsrpm --spec hello.spec --sources ./sources/
mock -r fedora-40-x86_64 --rebuild ./result/hello-1.0-1.src.rpm
